# Dual-Platform Parity

## Applicability

- Applies to: `team-architect`, all writers (`rule-writer`, `skill-writer`, `agent-writer`), `team-restructuring-master`
- Trigger condition: applies ONLY when a team maintains more than one platform tree — e.g. a Claude Code tree (`.claude/` + `CLAUDE.md`) alongside a Codex tree (`.codex/` + `AGENTS.md`), or any equivalent multi-runtime layout. Single-platform teams are out of scope.

## Rule Content

### M1 — Exactly One Canonical Source Design

Exactly one platform tree must be declared the canonical source design. The team's `CLAUDE.md` and `AGENTS.md` must both name it in a single, mutually consistent statement (e.g. "`.claude/` is the canonical source design; `.codex/` is generated from it"). Two trees each claiming to be the source, or neither naming a canonical, is a violation.

### M2 — Non-Canonical Trees Are Regenerated, Never Hand-Edited

Non-canonical trees must be produced by regeneration from the canonical tree. Hand-editing a generated (non-canonical) tree is a violation. To fix a defect that surfaces in a generated tree, fix the canonical tree first, then regenerate the non-canonical tree from it. The fix flows canonical → generated, never the reverse.

### M3 — Identical Version Stamp in Every Tree

The generator version stamp `Generated by A-Team on {yyyy-mm-dd}` must appear in the entry document of EVERY platform tree (`CLAUDE.md` for the Claude tree, `AGENTS.md` for the Codex tree, or the equivalent entry doc). After any regeneration, all trees carry the SAME date. Divergent dates mean the trees are out of sync and constitute drift.

### M4 — Restructuring Diffs Stamps First

`team-restructuring-master` (Phase 7) must diff the version stamps across all platform trees as its FIRST assessment step, before evaluating any other dimension. A missing stamp in any tree, or a stamp-date mismatch between trees, is classified as drift and reported ahead of all other findings. No structural change may be proposed until the stamp diff is recorded.

### M5 — Platform-Only Files Must Be Inventoried

Files that exist in a non-canonical tree with NO counterpart in the canonical source (platform-only runtime files, conversion artifacts, format mirrors) must be inventoried in a tracked document — a manifest or the conversion/format-mapping doc inside the team. The inventory lets regeneration prove zero silent drops: every non-canonical file is either regenerated from a canonical source or listed as an intentional platform-only file.

## Violation Determination

- M1: `grep -riE "source of truth|source design|canonical" CLAUDE.md AGENTS.md` yields zero canonical declaration, or two conflicting declarations → Violation.
- M2: a commit or diff modifies a non-canonical tree file whose content diverges from what regeneration from the canonical tree would produce (e.g. `.codex/` retrofitted while `.claude/` stays stale) → Violation.
- M3: `grep -rl "Generated by A-Team on" {each tree entry doc}` returns fewer hits than the number of platform trees, or the extracted dates differ across trees → Violation.
- M4: Phase 7 assessment `findings.md` records a structural recommendation with no preceding stamp-diff entry → Violation.
- M5: a non-canonical tree contains a file absent from both the canonical tree and the platform-only inventory → Violation.

## Exceptions

- A team that maintains a single platform tree is entirely out of scope; none of M1–M5 apply.
- Platform runtimes may require a fixed filename or directory layout the canonical format cannot express (e.g. `.toml` agent registries vs `.md`). Such structural transforms are permitted PROVIDED the transform is deterministic and documented in the M5 inventory/mapping doc — the transformed files still count as regenerated, not hand-edited.

Tradeoff: M2 forbids the fast path of patching the generated tree directly, forcing a canonical-edit-then-regenerate cycle on every change; regeneration costs one extra generation pass per fix. This buys guaranteed parity — the presentation-studio drift (Codex tree retrofitted, Claude tree stale, no stamp, undetected ~2 months) is exactly the failure this cost prevents.
