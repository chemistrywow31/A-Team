# Source Authority

## Applicability

- Applies to all writers, coordinators, restructuring assessments, and artifact reviewers.
- Trigger: team generation, existing-team maintenance, authority migration, or any multi-surface/reference-retained delivery.

## Rule Content

### M1 — Authority Is Explicit And Scoped

This branch's active canonical design is `.grok/` plus root `AGENTS.md`, declared through an explicit branch-native migration. `reference/platform-sources/` is a byte-preserved provenance/conversion snapshot and is not runnable or mutable authority. Main's authority remains unchanged. Never start Grok with the archive as cwd or treat an archived instruction as an active order.

Every generated team declares one authority, its canonical roots, requested format, runnable surfaces, and activation state in its team declaration and every runnable entry. A filename alone does not identify a runtime: read the declaration before interpreting `AGENTS.md`. A Grok-native single-surface team uses `AGENTS.md` plus `.grok/`; a platform-neutral source must explicitly identify its shared role/rule/skill families. An existing foreign authority remains authoritative until an explicitly authorized migration.

External-root writes require this complete gate:

1. Existing user authorization names one exact real root and the intended scoped work.
2. One declaration quorum identifies authority and roots; all runnable entries agree. A platform-neutral declaration uses `shared/team.yaml` with `canonical_authority.root: shared/` and declared role, rule, and skill families. Missing/conflicting authority permits read-only assessment only.
3. Multi-surface or conversion-retained Grok deliveries have `.grok/docs/format-mapping.md` and `.grok/docs/format-mapping.json`; authority, roots, runnable/reference-only states, and each assigned source/projection agree. A retained foreign manifest is evidence to reconcile, not a replacement authority invented by the writer.
4. Dispatch enumerates exact owned paths. Resolve the authorized root, every existing owned path, and the nearest existing parent of each new path. Reject `..`, outside absolute paths, and root/path/parent symlink escape.

Return `NEEDS_CONTEXT` without mutation for missing/conflicting declarations, dual-canonical claims, incomplete required mappings, or implicit reference-only promotion. Path escape fails closed. Directory presence and a nonempty mapping list are not proof of authority or full coverage.

### M2 — Classify Before Recommendations

First select capability maintenance, named-target maintenance, or explicitly requested fleet work. Capability improvement alone does not authorize target inventory or downstream writes. For a named target, record layout separately from runnable/activation state; classify Grok-only, foreign-platform source, multi-surface/reference-retained, non-team, or incomplete/activation-gated. Read stamps, canonical declaration, mapping completeness, and drift before proposing mutation.

Classify the defect as `Grok-only runtime gap` when confined to an inventoried native runtime surface, or `cross-platform design gap` when role intent, workflow, authority, shared semantics, or formats change. Ambiguous authority blocks writes, not bounded assessment.

### M3 — Edit Canonical First Under One Owner

Use `prompt-optimizer` only for text-only improvements leaving roles, rules, runtime, ownership, mappings, authority, and parity unchanged. Use `team-restructuring-master` for structural/runtime/parity work, then the `decision-auditor` recommendation gate before implementation. Record existing user authorization; ask only for uncovered material changes.

Capture exact preimages and family rollback. Change the declared canonical family first, then regenerate only assigned mapped projections sequentially under the same owner. A native runtime-only exception requires inventoried scope and exact targets; it does not exempt a whole tree or add another authority. Writers own only enumerated files, not entire eligible families.

Freeze producers for a coherent independent artifact gate. Verify semantics, references, mappings, stamps, and relevant executable checks; run preflight when active runtime artifacts change or current readiness evidence is absent. After corrections, invalidate changed-file and dependent mapping/parity criteria while retaining unrelated current evidence.

Rollback restores only owned task deltas from matching preimages and removes only recorded task-created files. Compare current bytes before restoration and preserve intervening edits. Never use blanket repository reset, cleanup, or archive deletion.

### M4 — Keep Stamps And Inventories Consistent

Every runnable entry carries `Generated by A-Team on {yyyy-mm-dd}`; regenerated runnable surfaces share the stamp. Mapping records requested format, unique authority, activation/reference states, exact source/target paths, platform-only assets, lossy adaptations, and reverse strategy.

A-Team's branch mapping uses schema version 1, `kind: a-team-designer`, exactly 13 roles/11 skills/19 policies, plus all other active targets. Its snapshot manifest covers 201 source files by bytes and Git mode; every archive file appears in mapping sources or justified source-only entries. These inventory counts apply to repo-self only. Generated teams use `kind: generated-team` with their accepted roster, and need no source snapshot for an unmapped single native surface.

### M5 — Fix Generator Defects At This Branch's Canonical Source

When target maintenance exposes a designer defect, fix the assigned `.grok/` canonical family and dependent native outputs before closing the work. Record downstream implications. Do not write main, archived sources, or real downstream teams without their separate exact authorization. Foreign active delivery belongs to an explicitly scoped conversion or the maintained source branch; do not activate archives implicitly.

## Violation Determination

- Authority or target classification is inferred from directory/filename presence, or a reference surface is promoted -> Violation.
- External writes lack exact root authorization, declaration quorum, full required mappings, or realpath confinement -> Violation.
- A design delta edits only a projection, bypasses recommendation review, or spans owners without reassignment -> Violation.
- Mapping counts from repo-self govern a generated team's roster, or source coverage/stamps drift -> Violation.
- A generator defect is fixed only downstream or rollback overwrites concurrent edits -> Violation.

## Exceptions

Unmapped single-surface teams need no conversion manifest or cross-surface stamp comparison; they still declare authority. Reference-only surfaces may omit runtime artifacts when all declarations label them non-runnable.

Tradeoff: Explicit mapping and independent gates add bounded work to structural changes. Keep ordinary text maintenance proportional and never use the archive's provenance checks as a lock on mutable native configuration or routine startup/recovery.
