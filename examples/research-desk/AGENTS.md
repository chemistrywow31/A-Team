# Research Desk

## Purpose and scope

Research Desk turns one decision question into a sourced brief. It finds sources, writes the brief, and checks that the claims match the sources. It does not publish the brief or contact the people named in the sources.

## Authority

Canonical authority for this team is Grok: root `AGENTS.md` plus `.grok/`. There is no second runnable surface. `briefs/` holds portable assignments rendered from the agent files. Those briefs are not agent definitions.

## Deployment

The current main session adopts `.grok/agents/research-lead.md`. Do not spawn a second lead.

Two ways to run the same roles:

- Grok Build loads the flat files in `.grok/agents/` and the rule in `.grok/rules/core.md`.
- A lead-and-helpers deployment hands `briefs/<role>.md` plus a task envelope to one direct specialist. That specialist starts with no conversation, returns one result to the lead, and does not spawn or message peers or the user.

`disallowedTools: [Task]` is the source-backed limit when a Grok client loads a specialist file. The brief repeats the same limit. Neither is proof that a live session enforced it until that session is observed.

## Role map

| Role | Owns | Returns |

| `research-lead` | Schedule, task board, owner report, final brief delivery | Status to the supervising owner |

The lead owns `.worklog/task-board.json` and `.worklog/owner-report.md`. Specialists do not edit those files.
